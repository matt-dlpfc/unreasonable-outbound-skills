# Checklist

Run before showing a tree. Fix what fails; if something can't be fixed, say so in *Unknowns*.

## The tree
- [ ] Outcome is what *their* board grades them on, in their words, with a figure.
- [ ] 2–4 engines, named the way the company names them, together covering most of the outcome.
- [ ] Every driver could be measured next quarter, and has a figure or `?`.
- [ ] Every behavior is a verb done by their people. No product names anywhere in the tree.
- [ ] Every pressure tag is dated, sourced, and sits on the node it hits (not all on the outcome).
- [ ] Owned: 1–2 behaviors per role, and the role really owns them (evidence in the table).
- [ ] No benchmark or guessed figure presented as theirs.
- [ ] Specific: swap in a competitor's name. Does the tree still read true? If yes, it's too generic.

## The path
- [ ] Every link from the owned behavior to the outcome is written out and believable.
- [ ] Deep: alternative paths include doing nothing and one non-software path, with an honest call on which their CFO would choose.
- [ ] *Where we fit* says plainly if the fit is weak.

## The conversation
- [ ] POV is about their business, not the product, and the target would want to confirm or correct it.
- [ ] Each opening question points at one node and carries a hypothesis.
- [ ] Unknowns are turned into questions, not hidden.

## The note
- [ ] Every figure and pressure has a row in *Evidence*, with source date and stated / inferred / aggregator.
- [ ] Mermaid renders (quotes, `<br/>`, no stray double quotes in labels), ≤ ~20 nodes.
- [ ] Quick: readable in ~5 minutes. Deep: the top (story, contact first, tree, POV, questions) still fits one screen and a half.
